# Avisos (toasts) com status, tempo e fechar — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Avisos com ícone de status (✓ verde / ✕ vermelho), barra de tempo de 4s e botão de fechar; no canto inferior esquerdo no computador e no topo no celular.

**Architecture:** Só muda `mostrarAviso` em `assets/js/site.js` (assinatura nova com `tipo`), os 6 chamadores em `assets/js/carrinho.js` e o bloco `.avisos`/`.aviso` de `assets/css/app.css`. Nenhum HTML muda: a área `[data-toast-area]` e o `[data-aviso-leitor]` já existem nas 6 páginas.

**Tech Stack:** HTML/CSS/JS puros (scripts globais com `defer`); `assets/css/app.css` é o único CSS (compilado, editado à mão).

**Spec:** `docs/superpowers/specs/2026-11-26-avisos-design.md`

## Global Constraints

- Assinatura: `mostrarAviso(tipo, titulo, detalhe)`, com `tipo` `'sucesso'` ou `'erro'`; `detalhe` opcional; sem parâmetro `foto`.
- Duração: 4000 ms; a barra encolhe de 100% a 0% no mesmo tempo, linear.
- Cores: sucesso `var(--color-success)`, erro `var(--color-error)`; cartão `var(--color-ink)`, como hoje.
- Fechar: `<button type="button" class="aviso-fechar" aria-label="Fechar aviso">` com ✕; remove com `.saindo` (fade de 0.2s) e depois tira do DOM.
- Posição: celular `top: calc(0.75rem + env(safe-area-inset-top))`, laterais 0.75rem, largura toda; a partir de `48rem`: `left: 1.5rem; bottom: 1.5rem; width: 24rem`, `top` e `right` em `auto`; `z-index: 80`.
- Leitor de tela: `[data-aviso-leitor]` recebe o título; com `tipo === 'erro'`, recebe `"Erro: " + titulo`.
- `prefers-reduced-motion`: sem animação de entrada; a barra continua.
- Loops no padrão `for (let i = 0; i < lista.length; i++)`; `site.js` usa aspas simples, `carrinho.js` usa aspas duplas.

## Review Focus

- Vários avisos seguidos (cliques rápidos no "+") → empilham, cada um com o próprio tempo e o próprio ✕; fechar um não fecha os outros. Verificado no passo de navegador da Task 2.
- Fechar no ✕ e o fim do tempo acontecendo juntos → o aviso some uma vez, sem erro no console (remover algo que já saiu do DOM não pode quebrar). Task 1, passo 3.
- Gaveta aberta no computador → o aviso aparece no canto inferior esquerdo, acima do fundo escuro e fora do painel. Task 2, passo de navegador.
- Celular com gaveta aberta → aviso no topo; o botão "Revisar e fechar pedido" continua visível. Task 2, passo de navegador.
- Título longo ("Adicione pelo menos um item antes de fechar o pedido.") → quebra em linhas dentro do cartão, sem empurrar o ✕ para fora. Task 2, passo de navegador.
